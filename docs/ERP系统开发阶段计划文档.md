## 一、文档说明

### 1.1 编制目的

本文档对 ERP 系统项目从需求确认到最终验收的全生命周期进行阶段划分，为每个阶段设定清晰、可衡量的目标（核心任务、关键里程碑、交付成果标准、验收条件），作为项目整体进度管理与质量管控的依据。

### 1.2 参考文档

本文档以下列文档为编制依据，各阶段工作须遵循对应文档的规范与设计：

| 参考文档 | 主要用途 |
|---------|---------|
| 《企业资源计划ERP系统需求规格说明书》 | 功能范围、实施计划框架、验收标准（第九节） |
| 《ERP系统开发技术选型》 | 技术栈版本基线 |
| 《ERP系统开发目录结构设计》 | 模块划分与工程结构 |
| 《ERP系统开发API设计与规范文档》 | 接口设计规范 |
| 《ERP系统数据库表结构设计文档》 | 数据库设计依据 |
| 《ERP系统开发编码规范文档》 | 编码与质量规范 |
| 《ERP后端重构规划方案》 | 后端开发阶段细分参考 |

### 1.3 术语约定

| 术语 | 说明 |
|------|------|
| SIT | 系统集成测试（System Integration Test） |
| UAT | 用户验收测试（User Acceptance Test） |
| M1~M10 | 项目里程碑编号 |
| D1~D9 | 开发与单元测试阶段内部子阶段编号 |
| 质量闸门 | 上一阶段验收条件未全部满足时，禁止进入下一阶段的管控机制 |
| Feature Complete | 功能开发全部完成，进入测试阶段的状态 |

## 二、总体规划

### 2.1 阶段总览

项目总周期 **12 个月**，共划分为 7 个阶段。宏观阶段以"第 N 月"计，开发阶段内部以"开发期第 N 周"计。

| 阶段 | 阶段名称 | 起止时间 | 核心目标 | 关键里程碑 |
|------|---------|---------|---------|-----------|
| 一 | 需求确认 | 第 1-2 月 | 需求调研与基线冻结 | M1 需求基线确认 |
| 二 | 系统设计 | 第 3-4 月 | 架构、数据库、接口、UI 设计定稿 | M2 设计评审通过 |
| 三 | 开发与单元测试 | 第 5-7 月 | 全模块编码实现（D1-D9） | M3~M7 |
| 四 | 集成测试（SIT） | 第 8 月 | 端到端全链路测试与性能验证 | M8 SIT 通过 |
| 五 | 用户验收测试（UAT） | 第 9 月 | 业务场景模拟验证 | M9（UAT 签字） |
| 六 | 数据迁移与上线 | 第 10 月 | 数据清洗迁移与系统切换 | M9（上线切换成功） |
| 七 | 上线支持与最终验收 | 第 11-12 月 | 驻场支持与终验 | M10 最终验收通过 |

### 2.2 阶段依赖关系

```mermaid
flowchart LR
    A[阶段一 需求确认] --> B[阶段二 系统设计]
    B --> C[阶段三 开发与单元测试]
    C --> D[阶段四 集成测试 SIT]
    D --> E[阶段五 用户验收测试 UAT]
    E --> F[阶段六 数据迁移与上线]
    F --> G[阶段七 上线支持与最终验收]
    C -.报表子阶段弹性顺延.-> D
```

## 三、阶段详细计划

### 阶段一：需求确认

| 要素 | 内容 |
|------|------|
| **阶段名称** | 需求确认 |
| **起止时间** | 第 1-2 月 |
| **阶段目标** | 完成业务调研与流程梳理，冻结需求基线，形成经业务部门确认的《需求规格说明书》终稿。 |
| **进入条件** | 项目立项完成，参与各方与关键用户名单确定。 |

**核心任务：**

| 任务 | 内容 |
|------|------|
| 1.1 业务调研 | 覆盖销售、采购、库存、生产、财务五大业务域的现状调研 |
| 1.2 流程梳理 | 输出各业务域现状流程图与目标流程图（As-Is / To-Be） |
| 1.3 需求编写 | 按《需求规格说明书》结构编写功能需求、接口需求、数据迁移需求 |
| 1.4 需求评审 | 组织业务部门逐章评审，记录并关闭评审问题 |
| 1.5 需求冻结 | 形成终稿并签字，建立需求变更管理流程 |

**关键里程碑：**
- **M1 需求基线确认**：《需求规格说明书》终稿经各业务部门负责人签字。

**交付成果标准：**
- 《需求规格说明书》（终稿）：功能模块覆盖基础数据、销售、采购、库存、生产制造、财务管理、报表与分析七大域，无"待定"条目；数据迁移需求含迁移对象、数据量预估、清洗规则、验证方案。

**验收条件（checklist）：**
- [ ] 七大业务域需求全部调研并写入文档，业务流程图完整
- [ ] 需求评审问题清单全部关闭
- [ ] 《需求规格说明书》终稿获得各业务部门负责人签字
- [ ] 需求变更管理流程已建立

---

### 阶段二：系统设计

| 要素 | 内容 |
|------|------|
| **阶段名称** | 系统设计 |
| **起止时间** | 第 3-4 月 |
| **阶段目标** | 基于冻结的需求基线完成架构、数据库、接口与 UI/UX 设计，通过设计评审，为编码提供完整设计依据。 |
| **进入条件** | M1 达成（需求基线冻结）。 |

**核心任务：**

| 任务 | 内容 |
|------|------|
| 2.1 架构设计 | 确定模块化单体架构与模块依赖关系（依据《目录结构设计》《技术选型》） |
| 2.2 数据库设计 | 按《数据库表结构设计文档》完成全量表结构、索引、约束设计 |
| 2.3 接口设计 | 按《API设计与规范文档》定义全部 RESTful 接口、统一响应体、错误码 |
| 2.4 编码规范确认 | 确认《编码规范文档》作为开发期强制规范 |
| 2.5 UI/UX 设计 | 完成核心页面原型与交互设计 |
| 2.6 设计评审 | 组织概要/详细/接口/数据库设计评审，问题闭环 |

**关键里程碑：**
- **M2 设计评审通过**：概要设计、详细设计、接口设计、数据库设计四类文档评审问题全部关闭。

**交付成果标准：**
- 《概要设计说明书》《详细设计说明书》《接口设计文档》《数据库设计文档》；接口文档覆盖全部规划接口并统一响应结构与错误码区间；数据库设计覆盖 40+ 业务表。

**验收条件（checklist）：**
- [ ] 架构与模块划分经评审确认，模块依赖关系明确
- [ ] 数据库表结构设计覆盖全部业务域，含索引与约束
- [ ] 接口文档覆盖全部规划接口，符合统一规范
- [ ] 设计评审问题清单全部关闭
- [ ] 四类设计文档归档入库

### 阶段三：开发与单元测试

| 要素 | 内容 |
|------|------|
| **阶段名称** | 开发与单元测试 |
| **起止时间** | 第 5-7 月（约 12 周，内部按 D1-D9 子阶段推进） |
| **阶段目标** | 按依赖链完成全部模块的后端与前端编码、单元测试和代码审查，达到 Feature Complete。 |
| **进入条件** | M2 达成（设计评审通过）。 |

#### 3.1 子阶段划分

各子阶段**后端与前端页面同步交付**，统一退出标准：**功能可联调 + 单元测试通过 + 代码审查完成 + API 文档与数据库脚本同步更新**。

| 子阶段 | 起止时间 | 核心任务 | 子阶段里程碑 |
|--------|---------|---------|-------------|
| **D1 骨架搭建** | 开发期第 1 周 | 父 POM 与模块划分；公共组件（统一响应体、全局异常、错误码、审计日志 AOP）；工程可编译可启动 | 工程骨架可编译、可启动 |
| **D2 系统管理** | 开发期第 2-3 周 | 认证与 JWT；用户/角色/权限管理；审计日志 | **M3 系统跑通**：登录接口返回 token，安全体系就绪 |
| **D3 基础数据** | 开发期第 4-5 周 | 物料/分类管理；BOM 管理（含闭环检测）；客户/供应商档案；仓库/库位 | **M4 基础数据完成**：主数据 CRUD 可用，BOM 闭环检测生效 |
| **D4 库存** | 开发期第 6 周 | 库存流水；批次管理；盘点；调拨；安全库存预警 | 库存增减全部经流水记录，数量可追溯 |
| **D5 采购** | 开发期第 7 周 | 采购申请→订单→收货→质检→入库；发票三单匹配；采购退货 | 采购全链路单据流转可演示 |
| **D6 销售** | 开发期第 8 周 | 销售订单→发货→出库；销售退货；订单跟踪；信用控制 | 销售全链路单据流转可演示 |
| **D7 生产** | 开发期第 9-10 周 | MRP 运算；生产工单；领料；报工；完工入库 | **M5 核心业务链完成**：销售→库存→采购→生产全链路单据流转可演示 |
| **D8 财务** | 开发期第 11-12 周 | 应收应付；存货核算（移动加权平均）；总账凭证自动生成；按工单成本归集 | **M6 业财一体完成**：出入库自动生成凭证，存货核算出成本 |
| **D9 报表与优化** | 穿插开发，第 12 周收尾 | 经营仪表盘；各业务模块报表；权限精细化；性能优化 | **M7 功能开发全部完成**（Feature Complete，含前端全部页面） |

> **弹性约定**：D9 报表如与第 7 月末的 Feature Complete 冲突，允许顺延至第 8 月与 SIT 并行开发，但仪表盘核心指标须在 SIT 结束前交付。

#### 3.2 阶段级交付成果标准

- 全部模块后端接口与前端页面完成并通过联调；
- 每模块单元测试通过，核心业务逻辑（BOM 闭环检测、库存计算、三单匹配、MRP、凭证生成）有单测覆盖；
- 全部代码符合《编码规范文档》，金额计算统一使用 BigDecimal；
- API 文档、数据库脚本与代码保持同步。

#### 3.3 阶段级验收条件（checklist）

- [ ] D1-D9 全部子阶段退出标准满足
- [ ] 销售→库存→采购→生产端到端数据流可完整演示
- [ ] 出入库单据自动生成财务凭证
- [ ] 前端全部页面可访问且与后端联调通过
- [ ] 单元测试全部通过，代码审查记录完整
- [ ] API 文档与数据库脚本为最新版本

### 阶段四：集成测试（SIT）

| 要素 | 内容 |
|------|------|
| **阶段名称** | 集成测试（SIT） |
| **起止时间** | 第 8 月 |
| **阶段目标** | 验证系统端到端业务流程的正确性与性能指标，暴露并修复集成缺陷。 |
| **进入条件** | M7 达成（Feature Complete）。 |

**核心任务：**

| 任务 | 内容 |
|------|------|
| 4.1 测试方案 | 编写 SIT 测试方案与端到端用例（覆盖"采购到付款""订单到现金"全链路） |
| 4.2 功能集成测试 | 执行端到端业务流程测试，记录缺陷并回归 |
| 4.3 性能测试 | 500 并发用户压测，验证事务成功率与响应时间 |
| 4.4 接口联调 | 与 OA、税控系统接口联调，验证数据双向传输 |
| 4.5 缺陷修复 | 缺陷分级修复、回归验证 |

**关键里程碑：**
- **M8 SIT 通过**：端到端全链路用例 100% 执行，致命/严重缺陷清零，性能与接口联调达标。

**交付成果标准：**
- 《集成测试报告》：含用例执行统计、缺陷分布与收敛曲线、性能测试结论、接口联调结论；缺陷修复记录完整。

**验收条件（checklist）：**
- [ ] 端到端全链路用例 100% 执行，通过率达标
- [ ] 致命、严重级别缺陷全部关闭
- [ ] 性能测试：500 并发用户下系统无崩溃，事务成功率 ≥ 99.9%
- [ ] 与 OA、税控系统接口联调通过，数据双向传输正常

### 阶段五：用户验收测试（UAT）

| 要素 | 内容 |
|------|------|
| **阶段名称** | 用户验收测试（UAT） |
| **起止时间** | 第 9 月 |
| **阶段目标** | 由各业务部门核心用户按实际业务场景模拟验证系统，确认系统满足业务需求。 |
| **进入条件** | M8 达成（SIT 通过）。 |

**核心任务：**

| 任务 | 内容 |
|------|------|
| 5.1 UAT 准备 | 编写 UAT 场景用例，准备演练环境与培训 |
| 5.2 用户测试 | 核心用户按实际业务场景执行测试（以 AC-300 变频器订单等端到端场景为主） |
| 5.3 问题处理 | 记录用户反馈问题，分级修复并回归 |
| 5.4 签字确认 | 各业务部门确认测试结果 |

**关键里程碑：**
- **M9（UAT 部分）**：UAT 测试报告经各业务部门核心用户确认。

**交付成果标准：**
- 《UAT测试报告》：场景覆盖说明、问题清单及处理结论、用户确认记录；同步完成《用户操作手册》初稿。

**验收条件（checklist）：**
- [ ] 核心业务流程（销售→生产→采购→入库→发货→财务）在 UAT 中完整测试通过
- [ ] 用户反馈问题全部闭环或经业务部门确认可接受
- [ ] 《UAT测试报告》获得各业务部门签字确认

### 阶段六：数据迁移与上线

| 要素 | 内容 |
|------|------|
| **阶段名称** | 数据迁移与上线 |
| **起止时间** | 第 10 月 |
| **阶段目标** | 完成旧系统数据清洗、迁移与验证，执行系统切换，正式上线运行。 |
| **进入条件** | M9 UAT 签字完成。 |

**核心任务：**

| 任务 | 内容 |
|------|------|
| 6.1 数据清洗 | 按《需求规格说明书》数据迁移需求执行：物料去重（一物多码合并）、BOM 闭环检查、客商编码统一 |
| 6.2 数据迁移 | 迁移物料主数据、BOM、客商档案、未结销售/采购订单、即时库存（以盘点数为准） |
| 6.3 迁移验证 | 按各迁移对象的验证方案核对（总量核对、抽样比对、误差率计算） |
| 6.4 上线切换 | 执行上线切换方案，完成切换演练与正式切换 |

**关键里程碑：**
- **M9（上线部分）**：系统切换成功，正式上线运行，《上线确认书》签署。

**交付成果标准：**
- 《数据迁移验证报告》：各迁移对象核对结果与误差率结论；《上线确认书》；上线切换方案与回退方案。

**验收条件（checklist）：**
- [ ] 全部迁移对象完成迁移并按验证方案核对
- [ ] 关键数据（库存数量/金额、未结订单金额）误差率 ≤ 0.1%
- [ ] 上线切换演练成功，回退方案可用
- [ ] 《上线确认书》签署，系统正式上线

---

### 阶段七：上线支持与最终验收

| 要素 | 内容 |
|------|------|
| **阶段名称** | 上线支持与最终验收 |
| **起止时间** | 第 11-12 月 |
| **阶段目标** | 保障系统稳定运行，完成运维与用户文档移交，通过最终验收。 |
| **进入条件** | M9 达成（上线切换成功）。 |

**核心任务：**

| 任务 | 内容 |
|------|------|
| 7.1 驻场支持 | 上线后驻场支持，处理运行问题（首月重点保障月结） |
| 7.2 问题修复 | 运行问题分级处理、修复与回归 |
| 7.3 文档移交 | 完善《运维手册》《用户操作手册》并培训移交 |
| 7.4 最终验收 | 组织终验评审，出具终验报告 |

**关键里程碑：**
- **M10 最终验收通过**：终验报告签署，项目交付完成。

**交付成果标准：**
- 《运维手册》《用户操作手册》：覆盖部署、日常运维、常见故障处理与各角色操作指引；最终验收报告。

**验收条件（checklist）：**
- [ ] 系统连续稳定运行达到约定观察期，无致命/严重问题遗留
- [ ] 首次月结在系统内完成
- [ ] 《运维手册》《用户操作手册》交付并完成培训
- [ ] 最终验收报告经各方签署

## 五、阶段间逻辑连贯性与质量管控

### 5.1 依赖链

各阶段目标按以下逻辑递进，环环相扣：

1. **需求 → 设计**：设计文档逐条对应需求条目，无需求无设计，保证范围不蔓延；
2. **设计 → 开发**：开发严格依据接口/数据库/编码规范，模块按依赖链推进（系统管理→基础数据→库存→采购→销售→生产→财务→报表），前序模块为后续模块提供数据与接口基础；
3. **开发 → SIT**：Feature Complete 后才进入集成测试，保证测试对象完整；
4. **SIT → UAT**：系统集成质量达标后，用户才基于稳定版本做业务验证；
5. **UAT → 迁移上线**：业务确认通过后迁移数据，避免在未验收系统上产生脏数据；
6. **上线 → 终验**：以实际运行观察期结果作为最终验收依据。

### 5.2 质量闸门机制

- **阶段闸门**：每阶段验收条件（checklist）逐条核对，未全部满足不得进入下一阶段；确需带条件进入的，须记录风险并明确关闭期限。
- **开发期子阶段闸门**：每个子阶段（D1-D9）统一退出标准——功能可联调、单元测试通过、代码审查完成、API 文档与数据库脚本同步更新。
- **里程碑复核**：M1-M10 在阶段例会上复核判定标准，判定结论记录归档。

### 5.3 进度跟踪

- 以子阶段（D1-D9）和里程碑（M1-M10）为最小跟踪单元，每周例会更新状态；
- 阶段偏差超过 1 周即触发纠偏措施（范围调整、资源增补或计划重排），并同步更新本文档的弹性约定。

## 六、风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|---------|
| 需求变更频繁 | 设计与开发返工 | M1 后冻结需求基线，变更走评审流程并评估工期影响 |
| BOM 闭环与多级展开复杂度高 | 基础数据与 MRP 受阻 | D3 优先实现并单测闭环检测；MRP（D7）复用同一展开算法 |
| MRP 运算性能不达标 | 生产计划响应慢 | D7 内做中等规模数据压测；必要时引入预计算与缓存策略 |
| 业财一体化凭证规则复杂 | 财务模块延期 | 设计阶段（2.2/2.3）提前冻结凭证模板与科目映射规则 |
| 外部接口（OA/税控）依赖方进度不可控 | SIT 接口联调受阻 | 第 8 月前完成接口规范确认与沙箱联调，预留联调缓冲 |
| 数据迁移误差超限 | 上线推迟 | 迁移前完成清洗规则演练与试迁移，正式迁移预留二次修正窗口 |
| 报表（D9）与测试期冲突 | Feature Complete 延后 | 允许 D9 弹性顺延与 SIT 并行，核心指标优先交付 |
