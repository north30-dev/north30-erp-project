| 状态 | 生效中 |
| 适用范围 | erp-frontend 全部业务页面开发 |

本计划基于后端 system 阶段（D2）已完成的 13 个 Controller 与前端基建提交 `c1a7f46`（认证、权限指令、路由守卫、request 封装、登录页）制定。开发最高原则沿用前端编码规范：**先约定、后编码**，所有管理页均为"页面模板三件套"的变体。

---

## 0. 总体划分

| 阶段 | 名称 | 交付物 | 前置依赖 |
|------|------|--------|---------|
| F0 | 基建补全 | AppSearchForm / AppCrudModal 公共组件、constants 枚举映射 | c1a7f46 基建 |

| F2 | 角色管理 | views/system/role 页面（含菜单分配、数据范围） | F1（页面范式复用） |
| F3 | 菜单管理 | views/system/menu 树形表格页面 | F2（联调权限链路） |
| F4 | 部门管理 | views/system/dept 树形页面 | F0 |
| F5 | 字典管理 | views/system/dict（类型 + 项两级页面） | F0 |

依赖说明：F1-F8 相互独立，可按序也可穿插开发；F1 必须最先做（作为页面范式的基准实现）；F9 收尾统一验证。

---

## F0 基建补全

**目标**：补齐"页面模板三件套"中缺失的两个公共组件，使后续每个管理页零样板成本。

**任务**：

1. `components/AppSearchForm/`：v-model 收集查询参数、搜索/重置按钮、插槽自定义字段。
2. `components/AppCrudModal/`：新增/编辑复用弹窗，`open(type, record?)` 驱动，内置 a-form 校验与提交 loading。
3. `constants/` 补齐枚举映射：用户状态、菜单类型、数据范围等数值常量与文案映射（与后端枚举值一一核对）。
4. 核对 `types/api.d.ts` 手写类型与最新后端 record 字段（后端历经分层重构，需逐域核对）。
5. 验证 v-perm 指令与路由守卫在真实 token 下工作正常。

**退出标准**：`npm run build` 通过；用一个临时 demo 页验证三件套组合可用后删除。

---

## F1 用户管理（页面范式基准）

**目标**：交付第一个完整管理页，确立所有后续页面的写法基准。

**任务**：

1. `api/user.ts`：对齐 SysUserController 全部接口（分页/详情/新增/更新/删除/状态/重置密码/分配角色），函数命名按规范 `动词+资源`。
2. `views/system/user/index.vue`：搜索表单（用户名/手机号/状态）+ 表格 + 新增/编辑弹窗 + 删除确认。
3. 扩展交互：状态开关（changeStatus）、重置密码弹窗、分配角色弹窗。
4. 列定义与表单字段超出 300 行时抽 `config.ts`（作为后续页面的示范做法）。
5. 按钮逐个挂 `v-perm`，权限点与 `sys_menu.perms` 逐一对照（如 `system:user:create`）。

**退出标准**：与后端真实联调通过（增删改查 + 状态 + 重置密码闭环）；自查清单 8 项全过。

---

## F2 角色管理

**目标**：交付角色管理页，首次落地"树形勾选"交互。

**任务**：

1. `api/role.ts`：角色 CRUD + 菜单分配 + 数据范围接口。
2. `views/system/role/index.vue`：三件套骨架。
3. 菜单分配弹窗：a-tree 勾选（半选父子联动，提交逻辑与后端 assignmenu 接口对齐）。
4. 数据范围（datascope）设置弹窗，枚举值走 constants 映射。

**退出标准**：角色创建 → 分配菜单 → 新用户授权该角色 → 登录后菜单/按钮权限生效，全链路验证。

---

## F3 菜单管理

**目标**：交付树形表格页面，打通"菜单即权限"的前端维护链路。

**任务**：

1. `api/menu.ts`：树查询 + CRUD。
2. `views/system/menu/index.vue`：a-table 树形展示（目录/菜单/按钮三类），类型切换时组件字段联动校验（与后端 SysMenu 充血校验规则一致的前端提示）。
3. 换父选择器（a-tree-select），后端有逐级防环校验，前端只做友好提示不做重复校验。

**退出标准**：新增按钮型菜单并配 perms 后，无需改前端代码即可出现在角色分配树中。

---

## F4 部门管理

**目标**：交付第二个树形页面（写法与 F3 对齐，仅数据结构差异）。

**任务**：

1. `api/dept.ts` + `views/system/dept/index.vue`。
2. 树形展示 + 换父（a-tree-select）；负责人、状态字段。
3. 用户页的部门选择下拉（F1 可预留）在本阶段后回接。

**退出标准**：树的增删改与换父联调通过；用户列表按部门过滤可用。

---

## F5 字典管理

**目标**：交付"主子表"两级页面范式。

**任务**：

1. `api/dict.ts`：字典类型 + 字典项两组接口。
2. `views/system/dict/index.vue`（类型页）+ `views/system/dict/item/index.vue`（项页，从类型页跳转携带 typeId）。
3. 字典项页作为 F1-F4 之外的第二种页面变体（主从跳转式），验证三件套适配性。

**退出标准**：新增字典 → 配置字典项 → 在其他页面通过 constants/api 消费该字典（首个消费点可为用户状态改造，非必须）。

---

## F6 参数配置

**目标**：交付最简单的标准 CRUD 页（A 类页面基准）。

**任务**：

1. `api/config.ts` + `views/system/config/index.vue`。
2. configKey 校验提示（小写域前缀.参数名格式）与后端规则一致。

**退出标准**：修改分页配置项后（system.page.default.size），刷新其他列表页生效。

---

## F7 日志查询（只读页）

**目标**：交付两个无弹窗的查询页变体。

**任务**：

1. `api/log.ts`：登录日志 + 审计日志分页查询。
2. `views/system/log/login/index.vue` 与 `views/system/log/audit/index.vue`：搜索区 + 表格，无新增/编辑；审计日志支持查看变更前后 JSON 详情（详情抽屉）。

**退出标准**：登录/操作产生的新日志能在页面实时查到（reload 验证）。

---

## F8 辅助域

**目标**：补齐 system 模块剩余页面。

**任务**：

1. `views/system/attachment/`：附件列表（按 bizType/bizId 查询；上传走前端直传模式，页面提供入口）。
2. `views/system/codesequence/`：编号序列查看与重置。
3. `views/system/importtask/`：导入任务列表（后端为占位实现，页面按契约先行，空数据不报错）。

**退出标准**：三个页面联调或契约验证通过；导入任务页在占位接口下正常渲染空态。

---

## F9 主布局与整体联调

**目标**：把所有页面装进应用壳，完成 system 阶段前端收尾。

**任务**：

1. 主布局：侧边栏（读取后端菜单树渲染，图标名对齐 `sys_menu.icon`）+ 顶栏（用户信息、退出登录）+ 标签页/面包屑。
2. 动态路由：登录后按菜单树注册业务页面路由（静态路由仅保留 login/404）。
3. 全模块回归：按 F1-F8 顺序过一遍核心链路（登录 → 菜单加载 → 各页 CRUD → 权限点验证）。
4. 收尾门禁：`npm run build` 零错误、无 console.log、无 any；API 文档与页面权限点核对表更新。

**退出标准**：admin 账号全功能可用；新建测试账号按角色分配后页面/按钮权限隔离正确；提交用户审查合并。

---

## 通用约束（各阶段均适用）

- 遵守《ERP系统开发前端编码规范文档》全部强制条款：三件套骨架、api 层契约类型、v-perm、constants 枚举映射、300 行拆分、TS 严格模式。
- 每阶段一个 feature 分支（命名如 `feature/frontend-user`），完成后由用户手动合并。
- 提交前逐项过规范文档第 10 节自查清单。
- 类型以后端 OpenAPI 契约为唯一事实源，禁止前端二次发明字段名。
