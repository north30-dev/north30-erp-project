# north30 ERP 全量安全审查报告

- **审查日期**：2026-10-28
- **审查范围**：全仓库 —— 后端 `erp-backend/`（311 个 Java 文件，5 Maven 模块，当前业务集中在 erp-common + erp-system 的 auth/user/role/menu/dept/dict/config/log/attachment 等域）与前端 `erp-frontend/src/`（32 个 Vue/TS 文件）
- **审查方法**：遵循 TRAE-security-review 方法论（Pass A 项目安全基线 → Pass B 偏差识别 → Pass C Source→Sink 全链路追踪）。仅报告具备明确攻击入口（Source）与危险汇聚点（Sink）、置信度 ≥ 0.80 的可证实风险；不包含 DoS/可用性、测试代码、文档类问题，不提供修复补丁代码。
- **审查维度**：用户指定 7 个维度（认证授权、注入/XSS/CSRF、敏感数据、越权、依赖漏洞、配置安全、输入输出校验），逐项结论见第 4 节。

## 1. 执行摘要

整体安全水位**良好**。项目安全基础设施设计规范：JWT 采用 HS256 + 强制密钥长度 ≥256bit + iss/exp 验签，配合 Redis 会话白名单实现登出/停用即时失效；所有业务接口均有 `@PreAuthorize` 权限点注解；SQL 全部经 MyBatis-Plus 参数化；口令 BCrypt 存储、手机号脱敏返回；附件存储有完整的路径穿越防御；前端无 `v-html`/`innerHTML` 使用，`pnpm audit` 无已知漏洞。

本次审查共确认 **3 项风险**（0 HIGH / 2 MEDIUM / 1 LOW），全部集中在**配置与降级策略**层面，未发现可直接利用的注入、越权或认证绕过漏洞。

## 3. 分维度审查结论

### 3.1 身份认证与授权机制（维度 1）

**结论：无发现，设计规范。**

- [SecurityConfig.java](file:///home/north30/projects/Personal/north30-erp-project/erp-backend/erp-bootstrap/src/main/java/me/north30/erp/config/SecurityConfig.java)：白名单显式列举（captcha/login/refresh/swagger/health），无通配放开业务路径；无状态会话；401/403 统一响应体。
- [JwtTokenProvider.java](file:///home/north30/projects/Personal/north30-erp-project/erp-backend/erp-common/src/main/java/me/north30/erp/common/jwt/JwtTokenProvider.java)：HS256，密钥 <32 字节启动即失败（L57-59）；解码器强制验签 + exp + iss 校验（L67-68）；access/refresh 用 type claim 严格隔离（L102-109），refresh token 无法访问业务接口。
- [JwtLoginUserConverter.java](file:///home/north30/projects/Personal/north30-erp-project/erp-backend/erp-system/src/main/java/me/north30/erp/system/security/JwtLoginUserConverter.java)：每次请求实时校验 Redis 会话白名单 + 账号状态 + 实时装载权限点，停用/登出即时生效。
- 登录防爆破：验证码（GETDEL 原子一次有效）+ 5 次失败锁 30 分钟 + 统一 18001 提示不泄露账号存在性（[SysAuthApplicationServiceImpl.java#L86-L134](file:///home/north30/projects/Personal/north30-erp-project/erp-backend/erp-system/src/main/java/me/north30/erp/system/auth/service/impl/SysAuthApplicationServiceImpl.java#L86-L134)）。
- 内置 admin 保护：修改/删除/停用均由实体守卫拦截（18012），且 `isAdmin` 无任何业务接口可写。

### 3.2 注入类漏洞：SQL 注入 / XSS / CSRF（维度 2）

**结论：无发现。**

- **SQL 注入**：全仓库无 Mapper XML、无 `@Select/@Update` 注解 SQL、无 `${}` 业务拼接（仅 POM 占位符）；`QueryWrapper.last()` 仅一处且为静态常量 `LIMIT 1`（[SysConfigDomainServiceImpl.java#L91](file:///home/north30/projects/Personal/north30-erp-project/erp-backend/erp-system/src/main/java/me/north30/erp/system/config/service/impl/SysConfigDomainServiceImpl.java#L91)）；其余查询全部走 `LambdaQueryWrapper` 参数化。
- **XSS**：前端无 `v-html`、无 `innerHTML`、无 `dangerouslySetInnerHTML`（全量 grep 为空）；Vue 3 模板默认转义；后端响应体为 JSON，无服务端模板渲染。
- **CSRF**：纯 API + `Authorization: Bearer` 头携带令牌（浏览器不会自动携带），无 Cookie 会话，`csrf.disable()` 属合理配置；CORS 仅放行 `http://localhost:*` / `127.0.0.1:*` 且 `allowCredentials=true` 只影响开发环境（[SecurityConfig.java#L93-L104](file:///home/north30/projects/Personal/north30-erp-project/erp-backend/erp-bootstrap/src/main/java/me/north30/erp/config/SecurityConfig.java#L93-L104)）——**部署提示**：生产如启用跨域需将来源收敛为真实域名。

### 3.3 敏感数据存储与传输（维度 3）

**结论：无发现（另有发现 #3 见上表）。**

- 口令：BCrypt(10) 单向存储，实体不回传；导出/列表 VO 均不含 password 字段；手机号经 `DesensitizeUtil.maskPhone` 脱敏（前 3 后 4）。
- 令牌：access 2h / refresh 7d，修改密码后强制全量会话失效；日志中无口令/令牌输出（仅 userId/username）。
- 传输：当前为 HTTP 本地开发；**部署提示**：生产必须前置 TLS（Nginx/网关），否则 Bearer 令牌可被链路窃听。

### 3.4 接口权限边界与越权（维度 4）

**结论：无发现。**

- 全部 56 处 `@PreAuthorize("hasAuthority('system:xxx:yyy')")` 覆盖 user/role/menu/dept/dict/config/log/attachment/sequence/importtask 各域所有读写接口（含 detail/list），无缺失权限注解的写接口。
- 权限点实时查库装载（非 token 内嵌），角色权限变更即时生效；权限点与 AdminInitializer 种子菜单一一对应。
- 管理端操作有资源存在性守卫 + 乐观锁 version（409），未发现水平越权缺口；当前无多租户/单据归属场景（单据域未开发），D4+ 交付单据接口时需复查 IDOR（数据范围 dataScope 机制已预留）。

### 3.5 依赖组件已知漏洞（维度 5）

**结论：无发现。**

- 前端：`pnpm audit` → **No known vulnerabilities found**。
- 后端版本基线均为当前主流无已知重大 CVE 的版本：Spring Boot 4.0.8（BOM 托管）、MyBatis-Plus 3.5.17、Hutool 5.8.47、springdoc 3.1.1、MapStruct 1.6.3、JDK 21。**方法局限**：Maven 侧未接入 OWASP dependency-check 类工具，本结论基于版本基线人工比对，建议后续在 CI 引入自动化扫描。

### 3.6 配置项与环境变量（维度 6）

**结论：2 项发现（#1 MEDIUM、#3 LOW，见上表）。**

- prod profile 全部敏感项（DB/Redis/JWT）环境变量化，`springdoc` 生产关闭（不泄露接口契约）；actuator 仅 `/health` 免认证且未开启额外端点暴露。
- 问题点：JWT secret 存在仓库内兜底值（#1）；dev 凭证明文（#3）。

### 3.7 输入输出校验与异常处理（维度 7）

**结论：无发现。**

- DTO 入参 `@Valid` + JSR-380 注解全覆盖，分页参数 `@Min(1)/@Max(200)` 限界；Service normalize 二次兜底。
- [GlobalExceptionHandler.java](file:///home/north30/projects/Personal/north30-erp-project/erp-backend/erp-common/src/main/java/me/north30/erp/common/exception/GlobalExceptionHandler.java)：500 兜底仅回固定文案，堆栈只入日志不回传；`HttpMessageNotReadableException` 不透出反序列化细节；405/404/参数类型错误均为固定/最小信息，无内部信息泄露。
- 附件上传：扩展名白名单（6 类）、大小/数量上限走 sys_config、文件名剥离路径分隔符与控制字符、存储路径服务端 UUID 生成、读取时 `normalize() + startsWith(storeRoot)` 双重路径穿越防御（[FileStorageStrategy.java#L119-L125](file:///home/north30/projects/Personal/north30-erp-project/erp-backend/erp-system/src/main/java/me/north30/erp/system/attachment/strategy/FileStorageStrategy.java#L119-L125)）。

## 4. 已检查但按方法论排除的项

| 项 | 排除理由 |
|----|---------|
| 前端双 token 存于 localStorage（[token.ts](file:///home/north30/projects/Personal/north30-erp-project/erp-frontend/src/utils/token.ts)） | 当前无任何 XSS 汇聚点（无 v-html/innerHTML），Vue 默认转义，链路不成立；属纵深防御建议——若未来引入富文本渲染，建议改 HttpOnly Cookie 方案 |
| 前端路由守卫仅客户端校验 | 方法论 §8.2：客户端权限检查不构成漏洞，服务端已逐接口鉴权 |
| 登录失败计数 `increment` 与 `expire` 非原子（[SysAuthApplicationServiceImpl.java#L126-L127](file:///home/north30/projects/Personal/north30-erp-project/erp-backend/erp-system/src/main/java/me/north30/erp/system/auth/service/impl/SysAuthApplicationServiceImpl.java#L126-L127)） | 异常场景只导致计数键无 TTL（可能永久锁定），属可用性问题而非可利用漏洞 |
| BCrypt 强度 10 | 当前算力下仍为可接受基线，属加固项非漏洞 |
| Swagger 白名单在 prod 仍放行路径 | prod 已通过 `springdoc.api-docs.enabled=false` 关闭，路径 404，无信息泄露 |
| 缺少 X-Frame-Options/CSP 等响应头 | 「缺失加固」不构成漏洞；建议后续在网关层统一补充 |

## 5. 修复优先级建议

1. **立即**（发现 #1）：JWT secret 生产兜底值加 fail-fast 校验，消除「漏配即沦陷」的单点。
2. **短期**（发现 #2）：将 Redis 降级策略从 fail-open 调整为登录路径 fail-safe，至少覆盖验证码与失败锁定两处。
3. **随期**（发现 #3）：dev 凭证与生产强隔离流程化；同时在 CI 引入 Maven 依赖漏洞扫描（如 OWASP dependency-check）补齐维度 5 的自动化能力。
