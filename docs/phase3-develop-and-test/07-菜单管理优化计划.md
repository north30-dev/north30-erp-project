## 1. 背景与问题清单

F3 菜单管理页面交付后发现以下问题（按严重程度排序）：

| # | 问题 | 现状 | 影响 |
|---|------|------|------|
| P1 | 父子类型校验缺失 | 后端 `requireValidParent` 只拦「按钮作父级」和防环，`菜单→菜单` 等结构实际可建 | 与文档「严格三级」不一致，树结构语义混乱 |
| P2 | 层级无上限 | 后端未校验深度，前端未限制「新增下级」 | 树嵌套过深破坏侧边栏/授权树可用性 |
| P3 | path/component/perms 无格式校验 | 前后端均只查非空 | 脏数据入库，F9 动态路由注册失败、白屏风险 |
| P4 | 权限标识手敲易错 | 前端为纯文本输入框 | 格式错误 + 与后端 `@PreAuthorize` 字符串对不上的双重风险 |
| P5 | 文档与实现不一致 | 文档写「严格三级」，代码可建越级结构 | 规则失去唯一事实源 |
| P6 | 存量数据未核查 | 未知 | 校验收紧后历史脏数据将无法编辑 |

## 2. 已确认的规则（唯一事实源）

### 2.1 父子类型规则（放宽版，替代文档原「严格三级」）

| 父级 | 允许的子类型 |
|------|-------------|
| 顶级(0) | 目录(1)、菜单(2) |
| 目录(1) | 目录(1)、菜单(2) |
| 菜单(2) | 菜单(2)、按钮(3) |
| 按钮(3) | 不允许（18023） |

概括为两条不变量：**按钮只能挂在菜单下**；**除按钮外，子类型不得小于父类型**。

关键决策记录：

- 跨级子仅放开「顶级→菜单」（工作台等独立页面的真实需求）；「目录→按钮」「顶级→按钮」禁止（按钮无页面上下文，会成为孤儿权限点）。
- 「菜单→目录」属于类型倒挂，禁止。

### 2.2 层级规则

- **限制深度，不限广度**：子节点数量不限制，最大深度 **4 层**（模块→子模块→页面→按钮）。
- 校验方式：一次全量查询 + 内存计算（父级深度向上回溯；换父级时需满足 `新深度 + 子树高度 - 1 <= 4`），**不加 level 字段**、不做配置项。
- 错误码：**复用 18023** `MENU_LEVEL_EXCEEDED`，文案修订为「菜单层级超过上限（最多 4 级）」（原计划新增 18028 `MENU_DEPTH_EXCEEDED`，因 18028 已被字典域 `DICT_TYPE_NOT_FOUND` 占用，且 18014-18023 菜单段已满，评审确认不新增错误码）。

### 2.3 字段格式规则（前后端同一语义）

| 字段 | 适用类型 | 规则 | 正则 | 示例 |
|------|---------|------|------|------|
| path | 目录/菜单 | `/` 开头，小写字母/数字/中划线，无连续/结尾斜杠 | `^/[a-z0-9-]+(?:/[a-z0-9-]+)*$` | `/system/menu` |
| component | 菜单 | 不以 `/` 开头、不以 `.vue` 结尾，至少两级；段允许大驼峰（与前端页面组件命名规范一致，2026-10-27 评审放宽） | `^[a-zA-Z0-9-]+(?:/[a-zA-Z0-9-]+)+$` | `system/loginLog/index` |
| perms | 按钮 | 固定三段 `模块:对象:动作`，小写 | `^[a-z][a-z0-9-]*:[a-z][a-z0-9-]*:[a-z][a-z0-9-]*$` | `system:menu:create` |

边界：不做 component 存在性校验（运行时无法访问前端文件树）；不做 path 唯一性前端校验（F9 路由注册冲突自然暴露）。

### 2.4 其余守卫（沿用/新增）

- 自指、防环校验保留（update 场景）。
- **有子节点时禁止修改菜单类型**，提示先处理子节点。
- 权限标识唯一性校验（`requirePermsAvailable`）已存在，保持。

## 3. 实施顺序

按「后端规则 → 后端格式 → 前端联动 → 前端体验 → 文档收尾」排序，每步可独立验证。

### 阶段一：后端父子校验与层级（P1/P2/P5 代码部分）

落点：`SysMenuDomainServiceImpl` / `SysMenuApplicationServiceImpl` / `SysMenu` / `ErrorCode`

1. ✅ `SysMenu` 新增静态充血方法 `requireValidChildType(Integer parentType, Integer childType)`：父子类型配对校验（父类型 vs 子类型，含顶级分支），只依赖类型值，不查库。错误码约定：按钮作父级 → 18023 `MENU_LEVEL_EXCEEDED`；其余配对违规 → 10001。（已完成，`erp-system` 菜单单测 43 例全绿）
2. ✅ `SysMenuDomainServiceImpl`（按校验**内容**命名，不按调用时机命名）：
   - `requireValidParent(parentId, childType)`：纯结构校验（父级存在性 + 委托 `requireValidChildType` 做类型配对），create/update 共用，签名中无 selfId；（已完成）
   - `requireNotDescendant(selfId, parentId)`：自指/防环校验，仅 update（换父级）时由编排层调用；（已完成，一次全量查询建 id→实体映射后回溯）
   - 深度校验：`requireDepthWithinLimit(parentId, childType)`（通用，父级深度 + 1 ≤ 4）与 `requireSubtreeDepthWithinLimit(selfId, newParentId)`（update 换父级专用，`新深度 + 子树高度 − 1 ≤ 4`）；实现为一次 `selectList(null)` 建 `id→parentId` 映射后内存计算，超限抛 18023。（已完成）
3. ✅ `SysMenuApplicationServiceImpl`：
   - `create`：`requireTypeFieldsValid()` → `requireValidParent` → `requireDepthWithinLimit` → `requirePermsAvailable` → 入库；（已完成）
   - `update`：先合并 DTO（`updateSysMenu`）得到最终 parentId/menuType，再依次执行：有子节点禁改类型守卫 → `requireTypeFieldsValid` → `requireValidParent`（合并后最终值）→（仅换父级时）`requireNotDescendant` + `requireSubtreeDepthWithinLimit` → `requirePermsAvailable` → 乐观锁入库。（已完成）
4. ✅ 错误码：复用 18023，文案修订为「菜单层级超过上限（最多 4 级）」（决策见 2.2）。
5. ✅ 单测（`mvn -pl erp-system -am test` 417 例全绿）：
   - 实体级：合法类型组合放行；顶级建菜单/按钮被拒；目录下建目录/按钮被拒；菜单下建菜单/目录被拒。
   - 领域级：防环、深度 4 层边界（第 4 层新增子节点被拒、换父级子树整体超限被拒）。
   - 应用级：update 先合并后校验、有子节点改类型被拒、换父级调用防环+子树深度守卫、未换父级不调深度守卫。
   - 新建 `MenuIntegrationTest`（erp-bootstrap，19 例全绿，幂等验证通过）：覆盖 2.1/2.2/2.3 正反用例、有子节点禁改类型、防环、perms 唯一、乐观锁 409/10601、鉴权轮次（401/403）。
6. ⏳ 存量数据核查（P6）：

   ```sql
   SELECT c.* FROM sys_menu c JOIN sys_menu p ON c.parent_id = p.id
   WHERE (p.menu_type = 3)
      OR (p.menu_type = 2 AND c.menu_type = 1)
      OR (p.menu_type = 1 AND c.menu_type = 3);
   ```

   结果非空需先清理；同时核查 `visible/status` 取值范围（0/1）。清理后无需数据迁移（`parent_id` 天然支持放宽后的结构）。

   **2026-10-27 核查结果（已清理）**：父子结构违规子树「测试(2) → 测测(1) → 111(1)」与格式全非法的「联调测试____」共 4 行，无角色引用，已物理删除。剩余「不合格」仅种子数据中 4 行 camelCase component（`system/loginLog/index` 等）——系前端页面组件大驼峰命名所致，属 2.3 正则与前端命名规范冲突，待评审放宽 component 正则，不作为脏数据删除。visible/status 无异常值。

## 4. 明确不做的事

- 不限制子节点数量（广度）——只限深度。
- 不加 `level` 字段、不做层级上限配置化——结构约束不是运行参数。
- 不做深度软限制（确认后放行）——树一旦变深，侧边栏/授权树实际损坏，无放行意义。
- 不做 component 存在性校验、path 前端唯一性校验——运行时无数据源，F9 动态路由兜底。
- 权限点清单接口（方案 B）不随本期做——推迟至 F9，理由见阶段四。
