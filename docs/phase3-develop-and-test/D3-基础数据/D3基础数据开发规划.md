## 一、阶段目标与进入条件

- **阶段目标**：在 `erp-base` 模块内完成物料分类、物料主数据、BOM（含闭环检测）、客户/供应商档案、仓库/库位的后端与前端同步交付，达到 M4 判定标准。
- **进入条件**：D2 退出标准满足（功能可联调 + 单测通过 + 代码审查完成 + API 文档与数据库脚本同步更新）。
- **退出标准**（子阶段统一闸门）：功能可联调 + 单元测试通过 + 代码审查完成 + API 文档与数据库脚本同步更新。

## 三、错误码号段（开工第一天一次预留到位）

按 project_memory 约定，base 域错误码落 **11001-11999**，按子域划分（见 API 文档 2.3）：

| 子域 | 号段 |
|------|------|
| 物料编码与分类 | 11001-11049 |
| 物料属性与状态 | 11050-11099 |
| BOM 结构与闭环/层级 | 11101-11159 |
| BOM 版本与审核 | 11160-11199 |
| 客户 | 11201-11249 |
| 供应商 | 11250-11299 |

- 新码一律取区间 max+1 追加，禁止按域数字连续回迁重排。
- 仓库/库位错误码（如 14004/14005/14006 在库存域使用）在 base 域建主数据时暂不新增，主数据停用校验复用 11003 类语义或新增 base 域码，需在开发时对照 API 文档确认。

## 四、数据表与建表要求

| 表 | 说明 | 关键约束 |
|----|------|---------|
| `base_material_category` | 物料分类树 | 树形（同 dept/menu 模式：parent_id、sort、乐观锁）；编码前 4 位与分类编码联动 |
| `base_material` | 物料主表 | `material_code` 唯一；`category_id` 必须叶子分类；`material_type` 1原材料/2半成品/3成品/4辅料；`status` 0新建/1审核/2启用/3停用；批次/保质期管理开关 |
| `base_material_code_map` | 旧码映射（一物多码，数据迁移预留） | `UNIQUE(old_code, source_dept)` |
| `base_bom` | BOM 主表 | `bom_code` 唯一；`UNIQUE(parent_material_id, version)`；同父件仅一个生效版本；状态 0草稿/1审核/2生效 |
| `base_bom_item` | BOM 明细 | `UNIQUE(bom_id, child_material_id)`；`child_qty > 0`；替代料字段（is_alternative / alternative_priority） |
| `base_customer` / `base_supplier` | 客商档案 | 编码唯一；启用/停用统一 `POST /{xxx}/{id}/status` |
| `base_warehouse` / `base_location` | 仓库/库位 | 库位归属仓库；为 D4 库存域预留关联 |

建表通用要求：继承 `BaseEntity` 审计字段（create_by/create_time/update_by/update_time/version/is_deleted/remark）、逻辑删除、无物理外键、金额数量 `DECIMAL(20,6)`。

> **说明**：base 域 9 张表已在 `database/init/00_schema.sql` 全量建好（`erp_db` 与 `erp_test_db` 同源），D3 开发**无需新建表**；若开发中发现 schema 与设计文档不一致，走 DDL 变更流程同步修改 00_schema.sql 并 ALTER 两库。

## 五、任务拆分与周计划

### 第 4 周：物料分类 + 物料主数据（打样，跑通树域模板）

| 任务 | 内容 |
|------|------|
| 1. 骨架 | 核对 00_schema.sql 中 base 域 9 张表与设计文档一致性（不新建表）；错误码枚举预留号段；base 模块分包 `me.north30.erp.base.{materialcategory, material, bom, customer, supplier, warehouse}` |
| 2. 物料分类域 | 分类树 CRUD（树查询/新增/修改/删除）；树域规则参照 dept/menu：`move` 上移下移接口、同级规范化重排、乐观锁冲突 409；删除校验「存在子节点/存在挂载物料不可删」（11006） |
| 3. 物料域 | 物料 CRUD + 按编码查询 + 审核/启用/停用 + 批量删除 + 导入导出 + 旧码映射；编码规则：分类编码前 4 位 + 6 位流水（11014 流水用尽防护，复用 system 域 codesequence 模式或 base 域内实现，需评审确认） |
| 4. 校验规则落地 | 编码与分类匹配（11004）、必须叶子分类（11005）、重复物料四要素提示（11008）、状态机（11003/11009/11010/11011）、计量单位走字典 `unit`（11016）、停用分类不可挂载（11017） |
| 5. 前端页面 | 物料分类树页（左树右列表布局）、物料管理页（列表/弹窗表单/审核启停/导入导出/旧码映射），套用 00-公共/10-全量页面美化方案 与 UI 规范（弹窗写操作、a-switch 状态列、图标 @ant-design/icons-vue） |
| 6. 单测 | 纯 Mockito + AssertJ + `@Nested`（命名 `shouldXxx_whenXxx`），覆盖全部校验规则与状态机 |

### 第 5 周：BOM（核心难点）+ 客商 + 仓库库位

| 任务 | 内容 |
|------|------|
| 1. BOM 闭环检测（最高优先级，风险项） | 新增/修改 BOM 时沿 `base_bom_item` 向下展开检测环（自引用/多级循环），命中返回 11102 并给出循环路径（如 `A → B → A`）；层级上限 10 层（11103）；**算法设计为可复用组件**，D7 MRP 展开复用同一展开器（阶段计划风险表要求） |
| 2. BOM 主子表与状态机 | 草稿→提交审核→审核→生效；同父件唯一生效版本（11107）、版本冲突（11106）、子件校验（未启用 11108 / 用量>0 11109 / 重复 11111 / 子件=父件 11104）、父件类型必须半成品/成品（11115）、生效版本不可删除（11113）、工单锁定预留（11117）；BOM 树形展开、where-used 反查、cycle-check 独立接口 |
| 3. 客户/供应商域 | CRUD + 启停（统一 status 接口）+ 客户信用额度查询（为 D6 信用控制预留）+ 供应商评级绩效查询（为 D5 预留）；错误码 11201-11299 |
| 4. 仓库/库位域 | 仓库 CRUD、库位分页 CRUD（库位归属仓库校验）；删除前校验无库存引用（当前无库存域，预留接口语义，D4 联调） |
| 5. 通用下拉 | `GET /api/base/options` 主数据下拉选项聚合接口（供各域前端复用） |
| 6. 前端页面 | BOM 管理（主子表编辑、树形展开视图、闭环校验提示、版本列表）、客户/供应商列表页、仓库/库位管理页 |
| 7. 集成测试 | 按 00-公共/05 实施方案新增 `BaseMaterialIntegrationTest` / `BaseBomIntegrationTest` 等，重点覆盖闭环检测负向用例；验收连续跑两遍全绿 |

## 六、架构与编码规范（强制）

- **小 DDD 模板**（编码规范 2.13）：Entity 局部充血（只校验自身状态+改自身字段+抛 BusinessException）→ `<domain>/strategy` 策略类（BomCycleCheckStrategy、MaterialCodeGeneratorStrategy、AssembleStrategy 等，按职责命名）→ ServiceImpl 只留编排，零私有方法仓库。
- **跨域禁止注入对方 Mapper**，一律走对方 Service 的 `requireXxx/listByXxx` 最小接口；本域关联表 Mapper 豁免。
- **跨模块**：erp-base 仅依赖 erp-common；如需字典校验（计量单位 unit）等 system 能力，按模块依赖规则确认调用方式（禁止 base → system 直接依赖，必要时经 common 抽象或在 bootstrap 层编排，评审确认）。
- Controller 只做参数校验/调 Service/封装响应；DTO/VO 一律 record；写接口标注 `@AuditLog`（仅 Controller 写方法）；分页参数 `@Min(1)/@Max(200)` + `@Valid`。
- Maven 命令陷阱：改过依赖模块源码后跑 bootstrap 测试必须 `mvn test -pl erp-bootstrap -am`。

## 七、里程碑 M4 判定标准

| 判定项 | 可客观验证 |
|--------|-----------|
| 主数据 CRUD 可用 | 物料/分类/BOM/客商/仓库/库位全部接口联调通过，前端页面可操作 |
| BOM 闭环检测拦截生效 | 构造自引用与多级循环用例，保存与 cycle-check 接口均返回 11102 且含循环路径 |
| 单测通过 | base 域单测全绿，闭环检测/编码生成/状态机有覆盖 |
| 集成测试 | base 域集成测试连续两遍全绿 |

## 八、风险与应对

| 风险 | 应对 |
|------|------|
| BOM 闭环与多级展开复杂度高（阶段计划风险表） | 第 5 周优先实现并单测闭环检测；展开器设计为独立可复用组件，供 D7 MRP 复用 |
| 物料编码流水生成方案未定（复用 system codesequence vs base 域自建） | 第 4 周开工前评审确认，避免编码规则返工 |
| 仓库/库位删除校验依赖尚未开发的库存域 | D3 先做主数据自身校验，引用校验接口留桩，D4 联调补齐 |
| base → system 字典依赖方向 | 开工前按模块依赖规则评审确认调用路径 |
